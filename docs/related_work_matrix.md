### CN01｜Web 应用访问控制漏洞检测研究进展（综述）

- **出处**：高技术通讯, 2025, 35(3): 227-240. 中科院计算所处理器芯片全国重点实验室
- **价值**：**你 §II 定义部分的标准引文**。它把访问控制漏洞正式分为
  - 功能级（BFLA）
  - **对象级（BOLA）** ← 你的目标
  - 对象属性级（BOPLA）
- **可引用的判断**：它明确指出"对象级和对象属性级漏洞的检测能力显著弱于功能级"。这句话可以直接用来论证选题必要性。
- **可打的点**：综述本身承认现有工作"评测口径不一"，但没有量化 —— 你的实证研究正好补齐。

> 引用句（中文写作可直接用）：

### CN02｜动态行为链 + 会话变异（计算机应用研究 2025）

- **方法**：Selenium 驱动浏览器执行"动作链"（多层操作序列）→ 流量代理中间件关联前后端 → 生成接口地图 → 基于角色/用户的会话变异生成攻击向量 → 规则引擎 + LLM 协同判响应
- **实验**：ShenYu、APISIX 等 6 个主流框架；20 个已知漏洞全部检出；接口覆盖率 89.2%；精确率 95.2%
- **实战**：在 SD-WebUI 发现水平越权（CVE-2024-31006）
- **优点**：接口覆盖率高，能处理"需要多步操作才触发的 API"
- **局限**：
  - 依赖 Selenium，**每个系统要写动作链脚本**，人工成本未量化
  - 6 个框架，但没有"无漏洞对照组"，精确率 95.2% 的分母不明确
  - 用 LLM 判响应 → 不可复现（模型版本会变）
- **对你的意义**：**这是你最直接的 competitor**。你的差异化必须至少覆盖两点：① 不需要手写动作链（用前端 bundle 自动恢复）；② 有对照组能量化 FPR。

### CN03｜响应相似性判定（信息安全学报 2025）★ 最重要的一篇

- **方法**：黑盒。用"响应**结构**相似性"把流量划分成接口，用"响应**内容**相似性"判断越权是否存在；只需客户端抓的流量，不需要服务器会话信息
- **实验**：9 个 Web 应用（74CMS、CRMEB、iWebShop、PHPSHE、StartBBS、极致CMS + 3 个校园网站）；生成 1262 个测试用例；**检出全部 9 个已知漏洞 + 10 个新漏洞**；1 个误报
- **性能**：平均判定 1.98 s；i7-7700 / 16 GB 单机
- **对比**：AppScan（只支持未授权+垂直，漏检且 4 个误报）
- **作者自述局限**（原文）：
  - "本方法仅考虑单一请求的越权操作，多操作才能触发的越权问题……可能带来路径爆炸问题"
  - "对网站访问流量的完整性有较高要求，访问流量的缺失会导致误报和漏报"
  - "当前测试的 Web 应用数量偏小"
- **⚠️ 一个必须注意的口径问题**：论文摘要和表 3 报的"查全率 99.9% / 查准率 98.7%"是**"越权待测接口识别"**的准确率，**不是漏洞检出率**。真正的漏洞检出在表 5（9 个已知全部检出，1 个误报）。
  → 这正是"指标口径不统一"的铁证，你在论文里可以客观指出，不要带情绪。
- **可打的点**：
  - 判据是"响应内容相似度"，对"结构相同、内容不同"的场景（分页、时间戳、随机 ID）敏感 → 你用字段级语义判定
  - 只支持单请求 → 你覆盖多步/写操作
  - 无对照组 → 你补

### CN04｜站点地图（计算机科学 2024）

- **方法**：为每个角色建独立站点地图 → 合并成完整站点地图 → 推断"预期访问控制策略" → 生成非法测试用例 → 动态执行验证
- **实验**：7 个开源 PHP 应用；PHP 5.3.10 + WampServer 2.2；页面覆盖率 >90%；发现 10 个真实漏洞；准确率 100%
- **局限**：
  - 需为每个角色人工爬站点地图，**角色多则成本线性上升**
  - 环境老旧（PHP 5.3），现代 SPA 不适用
  - "准确率 100%" 在 10 个漏洞的样本上，统计意义有限（无置信区间）
- **可打的点**：SPA/前端路由场景下站点地图失效 → 你用前端路由表 + AST 恢复接口

### CN05｜LLM4BOLA（信息安全研究 2026）

- **方法**：javalang 解析源码 → WALA 建调用图（Anderson 算法）→ LLM（DeepSeek-V3）推断"哪些表是敏感资源""用户表怎么关联""权限注解含义" → 定位缺失对象级校验的 SQL 操作
- **实验**：10 个开源 Java Web 应用（5 个有已知漏洞、5 个有未公开 BOLA）；**报告 88 条，69 条为真（含 52 个新发现）**；最好项目 TP 率 94.44%；1 例漏报 1 例误报
- **对比**：MACE-JAVA（把 MACE 适配到 Java，仍大量漏报）
- **价值**：**证明了"52 个新漏洞"意味着这个领域 ground truth 极度缺乏**——你建基准正好补这个洞
- **局限**：仅 Java、需源码、LLM 结果不可复现、新漏洞的"真值"靠人工验证

### CN06｜A2A 智能体（计算机应用 2026）

- **方法**：基于 MCP 的智能体，RAG 知识库（API 模式/框架特征/响应特征）+ 会话感知探索 + 异常响应线索挖掘 + 自适应探测
- **实验**：50 个 API（15 商业电商/金融、20 云服务、10 社交、5 多语言 CMS）+ 50 个非英文端点；API 发现率 91.9%，假发现率 7.8%
- **对比**：RESTler、ZAP、Burp Suite Pro、VOAPI2
- **价值**：**给了你现成的 baseline 数字**（ZAP 召回 56.7%、Burp 43.3% 等，见表），可以引用来说明"传统工具在 API 发现上就不行"
- **局限**：要调 LLM（有成本）；指标是"API 发现"不是"BOLA 检出"

### CN07｜状态偏离分析（计算机科学 2023）

- **方法**：白盒提取代码中访问控制约束 → 生成预期策略（有限状态机）→ 动态分析生成实际策略 → 检测两者偏离（ACVD 原型）
- **实验**：5 个开源 Web 应用；发现 16 个真实漏洞；查全率 98%；效率比传统黑盒提升约 300%
- **对比**：DetLogic、SDACV
- **局限**：**需要源码**（黑盒场景不可用）；只有 5 个应用；未报告查准率
- **可打的点**：白盒方法在"源码不可得 / 编译产物 / 前端渲染"场景失效 → 你是黑盒，互补而非竞争

### EN01｜OpenAPI → 着色 Petri 网（IJIS 2025）

- **方法**：把 OpenAPI 规范翻译成着色 Petri 网（CPN），把运行日志当 token 流，用**一致性检查**判断某个请求是否"越过了应有的授权状态"
- **实验**：Juice Shop 单案例（30 行日志）+ 1 个真实 BOLA 漏洞开源软件 + 用户评估
- **局限**：**只有案例研究，没有定量评测**；依赖 OpenAPI 规范存在（现实中大量 API 无文档）
- **价值**：形式化视角的对照，说明"有规范才能形式化"，而现实中恰恰没有规范 → 支撑你的"前端 bundle 恢复"路线

### EN02｜变异改进访问控制测试用例质量（JIS 2026）

- **方法**：为 CSRF/访问控制测试用例设计变异算子，用 mutation score 衡量测试用例质量
- **实验**：1 个 PHP 被测系统（4935 LoC），Infection PHP 框架

## 5. Related Work 段落草稿（中文，约 900 字，可直接改）

> **2 相关工作**
>
> **2.1 访问控制漏洞与对象级授权**
> 访问控制漏洞是 Web 应用中最常见的高危缺陷之一。OWASP 将其列为 API 安全风险首位 [OWASP]。按作用对象，文献 [CN01] 将其划分为功能级（BFLA）、对象级（BOLA）与对象属性级（BOPLA）三类，并指出后两类的自动化检测能力显著弱于功能级。对象级授权失效指服务端在访问由客户端提供的对象标识时，未校验该对象是否属于当前主体，攻击者仅需替换请求中的对象标识即可读取或篡改他人数据 [CN01][OWASP]。由于该过程不涉及注入特征，传统基于污点分析与模式匹配的扫描器难以覆盖。
>
> **2.2 检测方法**
> 现有工作可分为静态、动态与混合三类。
> 静态方法从源码提取授权约束。文献 [CN07] 将代码中的访问控制约束抽象为有限状态机，与实际执行轨迹比对以检测状态偏离，在 5 个开源应用上报告 98% 的查全率；文献 [CN05] 进一步引入大语言模型推断敏感资源表与权限注解语义，在 10 个 Java 项目上报告 69 个真实漏洞（其中 52 个为新发现）。此类方法依赖源码可得，且 [CN07] 未报告查准率、[CN05] 的 LLM 推理过程难以复现。
> 动态方法以黑盒方式重放变异请求。文献 [CN04] 为每个角色构建站点地图并据此推断预期访问策略，在 7 个 PHP 应用上发现 10 个真实漏洞；文献 [CN03] 利用 HTTP 响应结构与内容相似性划分接口并判定越权，在 9 个应用上生成 1262 个测试用例，报告 99.9% 的查全率与 98.7% 的查准率；文献 [CN02] 通过 Selenium 动作链与流量代理构建接口地图，并结合会话变异生成攻击向量，在 6 个 API 框架上实现 89.2% 的接口覆盖率与 95.2% 的精确率。上述方法的接口发现均依赖人工构造的浏览路径或完整流量，人工成本未被量化；[CN03] 亦自述其仅支持单一请求触发的越权。
> 智能体与形式化方法代表了新近尝试。[CN06] 基于 MCP 构建智能体，结合检索增强生成发现隐藏 API，在 50 个 API 上取得 91.9% 的发现率与 7.8% 的假发现率；[EN01] 将 OpenAPI 规范转换为着色 Petri 网并以一致性检查判定越权，但仅给出 Juice Shop 单案例的定性验证。
>
> **2.3 评测与基准**
> 尽管方法众多，评测基础设施却严重缺失。表 X 汇总了 7 项代表性工作的实验设置：其被测系统合计 70 余个，但相互重合度接近于零，且无一项公开其标注数据；所报告的"准确率"分别对应漏洞检出率、待测接口判定率、API 发现率等不同口径，其中 3 项未报告任何形式的误报率；**全部工作均未在已知无漏洞的系统上评估误报**，亦未单独建模多租户场景。文献 [CN05] 在 10 个项目中发现 52 个此前未知的 BOLA 漏洞，从侧面印证了该领域真实标注的匮乏。
> 因此，本文不提出又一个检测器，而是首先补齐评测基础设施，再在此基础上做方法探索。

> **英文版（润色后投 IEEE）**
> **Related Work.** Existing BOLA detection techniques fall into three families. *Static* approaches derive authorization constraints from source code: [CN07] encodes them as finite-state machines and detects state deviations, while [CN05] augments WALA-based call graphs with LLM-inferred resource semantics. Both require source access and report recall only or partially. *Dynamic* approaches replay mutated requests: [CN04] infers expected policies from per-role site maps, [CN03] partitions interfaces by response structure/content similarity, and [CN02] combines Selenium action chains with session mutation. All three rely on manually constructed browsing paths or complete traffic captures, and none quantifies the manual effort. *Agentic and formal* approaches are emerging: [CN06] uses an MCP-based agent with RAG for hidden-API discovery, and [EN01] translates OpenAPI specs into colored Petri nets for conformance checking, evaluated on a single Juice Shop case.
> Crucially, **no prior work releases its evaluation dataset**, and the reported "accuracy" spans at least five incompatible definitions (vulnerability-level P/R, interface-identification accuracy, API discovery rate, mutation score, and purely qualitative results). Three of seven papers report no false-positive rate at all, and **none evaluates on a known-secure system**. Multi-tenancy is never modeled separately. Our work therefore targets the evaluation infrastructure first.
